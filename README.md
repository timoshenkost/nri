# Листы персонажей D&D

Веб-листы на общем движке: **Стиви** (артифайсер), **Оникса** (друид) и
**Барди Би** (бард). Раньше это были копии одного кода, и каждое изменение
приходилось дублировать вручную. Теперь общая часть лежит в `common/` и
правится один раз.

## Раскладка

```
index.html          выбор персонажа
common/             общий движок — правится один раз, работает у обоих
  common.css          структура: карточки, модалка, тосты, поиск, ресурсы
  common.js           Store, esc, Modal, showNotice, rerender, initSearch,
                      groupByTags, Resources, Backup
  shell.css/js        оболочка: навигация, хиты, кошелёк, экспорт
  spellbook.css/js    движок книги заклинаний
  theme-tokens.md     список переменных, которые обязана задать тема
stivi/              только страницы Стиви
oniks/              только страницы Ониксы
bardi/              только страницы Барди Би
```

## Как это держится вместе

**Тема.** `common.css` не содержит ни одного конкретного цвета — только
`var(--…)`. Всё оформление задаёт `theme.css` в папке персонажа: медь и
чертёжная сетка у Стиви, фиолет и лунное свечение у Ониксы. Список токенов —
в `common/theme-tokens.md`.

**Вкладки не пересекаются.** Навигацию строит `shell.js` исключительно из
`CHARACTER.tabs` в `character.js`. Страницы одного персонажа не могут попасть
к другому: ни кнопки, ни `iframe`, ни загрузки файла. Схем у Ониксы нет,
обликов у Стиви нет — и появиться им неоткуда.

**Длительный отдых доходит до всех.** Кнопку отдыха жмут на одной вкладке,
а восстановиться должно везде: ячейки и способности в книге, заряды облика,
дневные изделия Стиви, хиты в самой оболочке. Оболочка рассылает команду
открытым вкладкам, но подставляет `iframe` только при первом открытии —
закрытая вкладка команду не услышит. Поэтому она же ставит метку
`long_rest_stamp`, а страница при загрузке сверяет её со своей через
`LongRest.catchUp(...)` и добирает пропущенный отдых. Новой странице с
ресурсами до отдыха нужны три строчки: `applyLongRest()`, ответ на
сообщение `long-rest-apply` с `LongRest.seen(...)` и `LongRest.catchUp(...)`
при запуске.

**Кошелёк общий для обоих.** Монеты живут в оболочке: кнопка 💰 в шапке
открывает кошелёк с четырьмя достоинствами. Курс из книги правил —
1 пм = 10 зм = 100 см = 1000 мм, поэтому итог считается в медяках и только
для показа переводится в золото. Ключ `money` входит в общее сохранение,
так что кошелёк переносится вместе с хитами и книгой.

**Данные разделены.** Все ключи `localStorage` получают префикс персонажа
(`stivi:my_hp`, `oniks:my_hp`). Это важно: хранилище привязано к origin, а не
к пути, поэтому без префикса два листа на одном домене затирали бы друг другу
хиты и книгу заклинаний. При первом запуске данные из версии без префиксов
переносятся автоматически.

## Как что-то поменять

| Задача | Куда идти |
|---|---|
| Новое заклинание | `<персонаж>/spells.js` |
| Больше ячеек, новая способность, другой максимум ОЗ | `<персонаж>/character.js` |
| Открыть круг повыше | `character.js` → `maxSpellLevel` и `slots` |
| Новая вкладка | `character.js` → `tabs`, плюс сам файл страницы |
| Цвета, шрифт, фон | `<персонаж>/theme.css` |
| Поведение книги заклинаний | `common/spellbook.js` — сразу у обоих |
| Общая утилита, модалка, поиск | `common/common.js` — сразу у обоих |

## Как собирается книга заклинаний

Книга складывается из двух источников:

1. **Список класса.** Персонаж объявляет `spellClasses` в `character.js`
   (например, `['Друид']`). Всё, что помечено этим классом в
   `common/spells.js`, попадает в книгу само — перечислять не нужно.
2. **Личные записи** из `<персонаж>/spells.js`. Здесь то, чего движок знать
   не может: что подготовлено, как это отыгрывается, где бесплатный каст,
   и заклинания **не из класса** — полученные от черт или вида.

Личная запись всегда сильнее: `prepared` и `roleplay` из неё побеждают
значения библиотеки. Имя — ключ связи; если оно не найдётся в библиотеке,
движок напишет об этом в консоль, а не молча потеряет заклинание.

**Фиксированные заговоры.** Необязательное поле `fixedCantrips: true` в
`character.js` означает, что заговоры выбраны при создании персонажа и не
меняются: список класса их не подтягивает, а кнопки подготовки у них не
появляются. Известные заговоры перечисляются в `<персонаж>/spells.js`.

**Фиксированный набор целиком.** Поле `fixedSpells: true` говорит, что
персонаж не подготавливает вообще ничего: и заговоры, и заклинания выбраны
при создании (так живёт Барди Би). Список класса тогда не подтягивает
ничего, `spellClasses` можно не задавать, а каждая запись из
`<персонаж>/spells.js` автоматически считается `locked` — писать `prepared`
и `locked` руками не нужно. Делить книгу надвое при этом не на что, поэтому
страница такого персонажа просто не заводит `available-list`: движок рисует
один список.

**Предел круга.** Необязательное поле `maxSpellLevel` в `character.js`
скрывает всё выше указанного круга — у Артефактора, который колдует в
половину уровня, высокие круги из списка класса только мешают искать.
Ограничение действует и на личные записи, но о них движок предупреждает в
консоли: молча терять выписанное вручную нельзя. Поднимать по мере роста
персонажа.

### Поля библиотеки (`common/spells.js`)

`name`, `levelNum`, `school`, `time`, `range`, `components`, `duration`,
`description` — механика из книги правил. Плюс:

- `classes` — список классов по next.dnd.su. **Определяет, кому заклинание
  подтянется автоматически.** Пустой массив означает «ещё не сверено»;
- `isConcentration` / `isRitual` — метки **К** и **Р**, выводятся из текста
  длительности и времени накладывания, руками их проставлять не нужно.

В библиотеке только редакция 2024 года. Если у заклинания на next.dnd.su вместо
описания стоит отсылка на 5e14.dnd.su, значит оно из прошлой редакции — такие
в библиотеку не берём, даже когда сайт числит их за нужным классом.

### Поля персонажа (`<персонаж>/spells.js`)

- `prepared` — подготовлено;
- `locked` — «всегда подготовлено», убрать нельзя; для таких заклинаний
  подготовленность всегда берётся из файла, а не из сохранения;
- `isFree` — один бесплатный каст до длительного отдыха;
- `roleplay` — как персонаж это делает;
- `mark` / `markTitle` — произвольный значок перед названием
  (`isMoon` поддержан как исторический синоним 🌙).

## Запуск

Открыть `index.html`. Локально лучше через сервер — на `file://` браузеры
по-разному изолируют `localStorage`:

```
python -m http.server 8777
```

Дальше <http://localhost:8777/>.

## Деплой

`.github/workflows/static.yml` выкладывает репозиторий на GitHub Pages при
пуше в `main`.
