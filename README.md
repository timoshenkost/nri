# Листы персонажей D&D

Два веб-листа на общем движке: **Стиви** (артифайсер) и **Оникс** (друид).
Раньше это были две копии одного кода, и каждое изменение приходилось
дублировать вручную. Теперь общая часть лежит в `common/` и правится один раз.

## Раскладка

```
index.html          выбор персонажа
common/             общий движок — правится один раз, работает у обоих
  common.css          структура: карточки, модалка, тосты, поиск, ресурсы
  common.js           Store, esc, Modal, showNotice, rerender, initSearch,
                      groupByTags, Resources, Backup
  shell.css/js        оболочка: навигация, хиты, временные хиты, экспорт
  spellbook.css/js    движок книги заклинаний
  theme-tokens.md     список переменных, которые обязана задать тема
stivi/              только страницы Стиви
oniks/              только страницы Оникса
```

## Как это держится вместе

**Тема.** `common.css` не содержит ни одного конкретного цвета — только
`var(--…)`. Всё оформление задаёт `theme.css` в папке персонажа: медь и
чертёжная сетка у Стиви, фиолет и лунное свечение у Оникса. Список токенов —
в `common/theme-tokens.md`.

**Вкладки не пересекаются.** Навигацию строит `shell.js` исключительно из
`CHARACTER.tabs` в `character.js`. Страницы одного персонажа не могут попасть
к другому: ни кнопки, ни `iframe`, ни загрузки файла. Схем у Оникса нет,
обликов у Стиви нет — и появиться им неоткуда.

**Данные разделены.** Все ключи `localStorage` получают префикс персонажа
(`stivi:my_hp`, `oniks:my_hp`). Это важно: хранилище привязано к origin, а не
к пути, поэтому без префикса два листа на одном домене затирали бы друг другу
хиты и книгу заклинаний. При первом запуске данные из версии без префиксов
переносятся автоматически.

## Как что-то поменять

| Задача | Куда идти |
|---|---|
| Новое заклинание | `<персонаж>/spells.js` |
| Больше ячеек, новая способность, другой максимум ОЗ | `<персонаж>/character.js` |
| Новая вкладка | `character.js` → `tabs`, плюс сам файл страницы |
| Цвета, шрифт, фон | `<персонаж>/theme.css` |
| Поведение книги заклинаний | `common/spellbook.js` — сразу у обоих |
| Общая утилита, модалка, поиск | `common/common.js` — сразу у обоих |

## Поля заклинания

`name`, `levelNum`, `school`, `time`, `range`, `components`, `duration`,
`description`, `roleplay` — описание. Плюс флаги:

- `prepared` — подготовлено;
- `locked` — «всегда подготовлено», убрать нельзя; для таких заклинаний
  подготовленность всегда берётся из файла, а не из сохранения;
- `isFree` — один бесплатный каст до длительного отдыха;
- `isConcentration` / `isRitual` — метки **К** и **Р**;
- `mark` / `markTitle` — произвольный значок перед названием
  (`isMoon` поддержан как исторический синоним 🌙).

## Запуск

Открыть `index.html`. Локально лучше через сервер — на `file://` браузеры
по-разному изолируют `localStorage`:

```
python -m http.server 8777
```

Дальше <http://localhost:8777/>.

## Деплой

`.github/workflows/static.yml` выкладывает репозиторий на GitHub Pages при
